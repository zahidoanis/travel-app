# TripAI

עוזר נסיעות חכם בעברית ובאנגלית — **אתר רספונסיבי** (Progressive Web App), לא
אפליקציה נייטיב. React + Vite, RTL מלא. רץ בכל דפדפן, במובייל ובדסקטופ, וגם
בלי חיבור לאינטרנט אחרי ביקור אחד.

## הרצה מהירה

```bash
npm install
npm run dev
```

נפתח ב-http://localhost:5173. עובד מיד, בלי שום הגדרה: בלי Firebase הכול נשמר
במכשיר, ובלי מפתח AI הצ'אט מציג שהסוכן אינו מחובר.

| פקודה | מה היא עושה |
|---|---|
| `npm run dev` | שרת פיתוח עם hot reload |
| `npm run build` | בונה ל-`dist/` |
| `npm run preview` | מגיש את ה-build המקומי |
| `npm test` | בדיקות יחידה — חלוקת הוצאות ותאריכים |
| `npm run rules:test` | כללי האבטחה מול האמולטור המקומי (ראו [בדיקות](#בדיקות)) |
| `npm run i18n:check` | כל מחרוזת בממשק מתורגמת לאנגלית |
| `npm run legal:check` | פרטי מפעיל האתר מולאו (ראו [LEGAL.md](LEGAL.md)) |
| `npm run ai:check` | מאמת את מפתח Gemini ושהדגם באמת עונה |

**דרישה:** Node.js 18 ומעלה. נבדק על Node 22.

## מה יש באפליקציה

| מסך | מה יש בו |
|---|---|
| **פתיחה ושאלון** | יעד, תאריכים, מי נוסע, סגנון, אוכל, טיסה ולינה. אפשר לייבא טיול מ-Google Maps. |
| **בית** | מזג אוויר אמיתי ליעד, התכנון של היום, הערות, וקיצורי דרך לשאר המסכים. |
| **מפה** | העצירות של היום על מפת OpenStreetMap, ניווט, ומיקום חי של חברי הטיול (בהסכמה). |
| **צ'אט** | סוכן AI שמכיר את הטיול, מציע מקומות ומשנה את המסלול — ושואל לפני שהוא מוחק או בונה יום מחדש. |
| **מסלול** | כל ימי הטיול, הוספה, סידור והעברה של עצירות, ותכנון יום משותף לכמה משפחות. |
| **הזמנות** | רישום הזמנות וכרטיסים, עם צילום של הכרטיס. |
| **פיננסים** | המרת מטבע בשערים חיים, והוצאות משותפות: מאזן לכל משפחה ומי מעביר למי כדי להתאזן. |
| **מסעדות, הגעה, מלונות** | המלצות, איך מגיעים משדה התעופה, ומקומות לינה. |
| **סיכום להדפסה** | הטיול כמסמך אחד, להדפסה או לשמירה כ-PDF. |
| **מדיניות פרטיות, תנאי שימוש, הצהרת נגישות** | בכתובות `/privacy`, `/terms`, `/accessibility` — ראו [LEGAL.md](LEGAL.md). |

כל שינוי במסלול (הסרת עצירה, העברה, בנייה מחדש, שינויים של הסוכן) מציג הודעה
עם **בטל**. מחיקת דברים שאין להם ביטול — הוצאה, הערה, הזמנה, תמונת כרטיס, טיול,
חשבון — מבקשת אישור.

## מסד הנתונים וסנכרון

Cloud Firestore בתוכנית Spark. כל מכשיר מקבל חשבון אנונימי בלי הרשמה, ו"שמור
את הטיול" מחבר אותו לחשבון Google בלי לאבד דבר.

```
users/{uid}                                   פרופיל: הטיול הפתוח
trips/{tripId}                                הטיול, memberIds, ההוצאות, ההערות, ההזמנות
trips/{tripId}/families/{familyId}/routes/…   התכנון של כל משפחה, יום אחר יום
trips/{tripId}/families/shared/routes/…       ימים שמתוכננים יחד
trips/{tripId}/tickets/{id}                   תמונות כרטיסים
trips/{tripId}/activity/{id}                  ההתראות בפעמון
trips/{tripId}/presence/{uid}                 מיקום חי, רק למי ששיתף
diagnostics/{uid}/events/{id}                 יומן תקלות, כתיבה בלבד
```

- **הטיול חי.** מסמך הטיול והמסלולים נצפים בזמן אמת, כך שהוצאה או הערה של חבר
  אחד מופיעות אצל כולם בלי רענון.
- **שמירה בלי לדרוס.** רשימות (הוצאות, הערות, הזמנות, משפחות, זיכרון הסוכן)
  נשמרות בטרנזקציה מול העותק העדכני בשרת, כך ששני אנשים ששומרים באותו רגע לא
  מוחקים זה לזה. נבדק מול האמולטור: 12 מתוך 12 שמירות בו-זמניות נשמרו.
- **בלי Firebase** הכול נשמר ב-localStorage, באותו ממשק.

## שיתוף והזמנות

קישור ההזמנה נושא את מזהה הטיול ו-`inviteToken`. כללי האבטחה מאפשרים להצטרף
רק למי שמחזיק בשניהם, ורק כעורך — לא כבעלים, ובלי לשנות אחרים. כל חבר יכול
ליצור קישור חדש ממסך השיתוף, וכל הקישורים הקודמים מפסיקים לעבוד. טיולים שנוצרו
לפני שהיו טוקנים מצטרפים לפי המזהה בלבד, עד שמישהו יוצר להם קישור חדש.

## סוכן ה-AI

| מצב | תנאי | התנהגות |
|---|---|---|
| **כבוי** | שום דבר לא מוגדר | הצ'אט מציג שהסוכן אינו מחובר |
| **פיתוח** | `VITE_GEMINI_API_KEY` | הדפדפן קורא ל-Gemini ישירות — המפתח גלוי בקוד |
| **פרודקשן** | `VITE_AI_PROXY_URL` | קריאה לפרוקסי שמחזיק את המפתח |

כשגם פרוקסי וגם מפתח מוגדרים, הפרוקסי מנצח.

### הקמה — פרודקשן

```bash
npm install -g wrangler
cd worker
wrangler login
wrangler secret put GEMINI_API_KEY
wrangler deploy
```

`ALLOWED_ORIGINS` ב-`worker/wrangler.toml` הם הדומיינים שרשאים לקרוא לפרוקסי.
בקשה ממקום אחר נדחית לפני שהיא מגיעה ל-Gemini. בדיקה: `npm run worker:check`.

### מה הסוכן יודע ומה מותר לו

[`systemPrompt()`](src/lib/gemini.js) נותן לו את היעד, הימים, המסלול, הרכב
הקבוצה, מה שהוא זוכר משיחות קודמות ומזג האוויר. הוא משנה את המסלול רק דרך שורות
פעולה שהאפליקציה מבצעת ומדווחת עליהן בעצמה. **בנייה מחדש של יום שיש בו עצירות
והסרת עצירה דורשות אישור** — הקלט שלו כולל תוצאות חיפוש, תיאורים ממפות מיובאות
והערות של אחרים, ואף אחד מהם לא אמור להיות מסוגל למחוק יום. כל השינויים מתשובה
אחת מתבטלים יחד.

> **מכסה ופרטיות:** השכבה החינמית של Gemini מוגבלת לכמה מאות בקשות ביום,
> ו-Google משתמשת בתוכן שנשלח אליה. לפני השקה — ראו [LEGAL.md](LEGAL.md).

## מפות

אריחי OpenStreetMap, בלי מפתח. [`tiles.js`](src/lib/tiles.js) מממש Web
Mercator ו-[`MapCanvas.jsx`](src/components/MapCanvas.jsx) מרכיב את האריחים ושכבת
SVG של המסלול. הזום קבוע (14), ומתרחק רק כשיום פרוש על שטח גדול מדי, כדי שיום
אחד לא יטען יותר מ-150 אריחים.

> **קרדיט הוא תנאי רישיון** — מוצג בפינת המפה.
> **שרתי האריחים של OpenStreetMap אינם מיועדים לתעבורה מסחרית.** לפני שהאתר
> גדל — ספק אריחים (MapTiler, Stadia, Protomaps). חיבור Google Maps: [MAPS.md](MAPS.md).

## עבודה בלי חיבור

[`public/sw.js`](public/sw.js) שומר את קבצי האפליקציה עצמה: דפים מהרשת קודם
(עדכון נקלט מיד כשיש חיבור), קבצי `/assets` מהמטמון (שמם כולל hash). נתוני
הטיול נשמרים בנפרד במטמון של Firestore. יחד: אחרי ביקור אחד, האפליקציה נפתחת
על הטיול גם בלי רשת. ה-service worker לא נוגע ב-Firebase, ב-AI, באריחים או
בדפי ההתחברות של Firebase (`/__/`).

## יומן תקלות

[`telemetry.js`](src/lib/telemetry.js) תופס חריגות, Promise שנדחו, קריסות רינדור
(לכל מסך בנפרד), כשלי רשת, `console.error`, תקיעות ממשק ופעולות שלא הסתיימו.
כל רשומה נושאת את 20 הפעולות האחרונות. נכתב קודם ל-localStorage ואז ל-Firestore
(`diagnostics/{uid}/events`), שם הוא **כתיבה בלבד** מהדפדפן — קוראים אותו מקונסולת
Firebase. כל רשומה מקבלת `expireAt` של 90 יום; המחיקה בפועל דורשת מדיניות TTL —
ראו [LEGAL.md](LEGAL.md).

## בדיקות

| | |
|---|---|
| `npm test` | בדיקות יחידה: חלוקת הוצאות, פענוח סכומים, תאריכים |
| `npm run rules:test` | 23 מקרים של כללי האבטחה, מכל צד — מי שאמור להיכנס ומי שלא |

```bash
npx firebase-tools@13 emulators:start --only auth,firestore --project demo-tripai

```

אפשר גם להריץ את האפליקציה עצמה מול האמולטור — כדי לבדוק הצטרפות, סנכרון בין
שני דפדפנים או מחיקת חשבון בלי לגעת בפרודקשן:

```
VITE_FB_API_KEY=demo  VITE_FB_PROJECT_ID=demo-tripai  VITE_FB_EMULATOR=1  npm run dev
```

## משתני סביבה

כולם אופציונליים. מעתיקים מ-[`.env.example`](.env.example) ל-`.env.local`.

| משתנה | תפקיד |
|---|---|
| `VITE_FB_*` | פרויקט Firebase. בלעדיהם הכול נשמר במכשיר. |
| `VITE_FB_EMULATOR` | `1` = עבודה מול האמולטור המקומי |
| `VITE_AI_PROXY_URL` | פרוקסי ה-AI. גובר על המפתח הישיר. |
| `VITE_GEMINI_API_KEY` | מפתח Gemini לקריאה ישירה (פיתוח בלבד) |
| `VITE_GEMINI_MODEL` | דגם. בדיקת זמינות: `npm run ai:check` |
| `VITE_GOOGLE_MAPS_KEY` | מעביר את המפה ל-Google Static Maps |

Vite קורא את הקבצים האלה רק באתחול.

## פריסה

```bash
npm run legal:check && npm test && npm run build
firebase deploy --only hosting
npm run rules:deploy                 # כשהשתנה firebase.rules
cd worker && wrangler deploy         # כשהשתנה worker/
```

[`firebase.json`](firebase.json) מגדיר: rewrite של SPA, cache ארוך ל-`/assets`,
בלי cache לדפים ול-`sw.js`, וכותרות אבטחה (CSP ועוד). **אל תריצו `firebase init`**
— הוא דורס את הקובץ. המדריך המלא: [DEPLOY.md](DEPLOY.md). מה חובה לפני השקה:
[LEGAL.md](LEGAL.md).

## החלטות עיצוב

**RTL עם logical properties** — `inset-inline-start`, `margin-inline-end` במקום
`left`/`right`. בעמודת flex תחת RTL ציר הרוחב מתהפך.

**טוקנים לצבע, מרווח ורדיוס** ב-`:root`, וערכות נושא ב-`theme-*.css`. הפעילה
היא `cream` (ב-[`theme.js`](src/theme.js)), שבה כל טקסט עומד בניגודיות 4.5:1.

**כסף באגורות** — כל החישובים ב-[`split.js`](src/lib/split.js) במספרים שלמים, כדי
שהמאזנים תמיד מסתכמים לאפס.

**"היום" לפי היומן המקומי** — לא לפי `toISOString()`, שבישראל הוא עדיין אתמול
עד 2–3 בלילה.
